## Compatibility and operational state decision

Actual Appointment v1 response models restrict state to confirmed/cancelled and journey_id to null. Records creation and Appointment clinical holds require confirmed. Widening those models in place would break strict clients. Therefore preserve v1 booking state and null journey_id, including private consultation/billing contexts. New operational state lives in an Appointment-owned `appointment_workflows` table and new `/workflow` resources. A confirmed booking reserves its original slot even after workflow completion/no-show; the historical booking state is not rewritten to release a future slot. Cancellation still changes v1 state to cancelled.

After coordinated activation, every newly booked/promoted appointment atomically creates one workflow and one journey. Historical appointments are not silently enrolled or backfilled: receptionist enrollment is explicit, allowed only for future confirmed appointments without any clinical hold. Existing finalized records/dispensings/invoices keep nullable journey refs; projection joins by verified appointment_id and patient_id. Rescheduling retains the episode ID, before check-in only. Historical unenrolled Phase 2 clinical creation remains usable. For an enrolled appointment, Records creation requires the workflow in_consultation state; this is an explicit safety gate for the new workflow, tested against the legacy path. Records checks the new leaf before acquiring its existing hold. Appointment rechecks that gate under locks when acquiring the hold. Finalize/retry of an existing hold must remain recoverable.

Activation is one reviewed integrator release after all dependency gates. Shared hooks default disabled before then; no partially installed module can change existing behavior. No new v2 booking API is needed because the new resource has its own semantics and all old response enums/fields remain intact.

## Common wire protocol

Definitions from Phase 2 apply: ID is a positive decimal string <=9223372036854775807; Version is a strict integer 1..9007199254740991; Time is UTC RFC 3339; Date is YYYY-MM-DD; Reason is trimmed 1..500 characters; Quantity 1..1000000; Minor is a strict nonnegative safe integer; currency INR. `?` alone marks optional fields; all other fields including nullable fields are required. Unknown body/query fields and duplicate query keys return 422. No number IDs, booleans as integers, client-generated totals or arbitrary state PATCH.

Every public route checks valid existing Bearer access JWT, current Patient authority and resource scope. Staff roles alone never grant clinical access. Self means principal.patient_id equals stored patient_id, never principal.sub. Own doctor means sub equals the stored doctor_user_id, with current doctor authority. Ops/admin have no new business access unless they also hold an allowed role. Unauthorized resources are concealed with 404; role denial 403; invalid identity 401. No public token-only check-in or trusted actor headers.

Every POST command requires the existing 16..128 printable non-space ASCII Idempotency-Key. Scope is user or authenticated service principal, method, actual resource path and key. Hash normalized body plus If-Match; same key/different command 409 conflict. Authorize before replay, replay before stale-version rejection. Equal concurrent keys yield one business effect and original status/body/ETag. Keep responses >=24 h; business uniqueness survives expiration. Store token digests rather than raw tokens in request fingerprints and never raw tokens in persisted responses. Token issuance is the explicit exception described below.

All commands targeting an existing aggregate require exact quoted If-Match from that aggregate's GET, as identified in route tables. Missing 428 precondition_required, malformed 400 bad_request, stale 412 version_conflict. Successful single-resource reads/commands return its ETag and Cache-Control: no-store; lists have no ETag unless explicitly a queue snapshot. Headers preserve X-Request-ID, X-Correlation-ID and traceparent. Mutation + ordered audit + outbox + persisted result is one owning transaction. No DB locks across network calls. GET never enrolls, expires, consumes, promotes or reconciles. Register new static waitlists/waitlist-slots/queues/queue-entries/journeys routes before the existing `/{appointment_id}` matcher; path-ID validation is not a routing fallback. Agent 1 owns router ordering and duplicate method/path detection within Appointment. Different private services may intentionally expose the same path with distinct owner authentication.

Error envelope: `{error:{code:string,message:string,request_id:UUID,details?:object}}`. Details may identify field paths or a nonsecret resource ID for token reissue, never field values, raw tokens or clinical content. Codes: 400 bad_request; 401 unauthorized; 403 forbidden; 404 not_found; 409 conflict or named business conflicts below; 412 version_conflict; 422 validation_error/invalid_reference; 428 precondition_required; 429 rate_limited; 503 dependency_unavailable; 504 dependency_timeout; 500 internal_error. 503/429 Retry-After: 1 is a proposed bound, not a throughput result. Existing authority helper retains its 2-second timeout/503 behavior. New dependency calls: <=1 second, at most two safe read attempts with 50..150 ms jitter within 5-second request deadline; invalid/oversized (>256 KiB) snapshots fail 503; timeout 504; no redirects. Circuit: five transport/5xx failures, 15-second open period, one half-open probe. Values are prototype policies, not measured tuning.

`Page<T>={items:[T],next_cursor:string|null}`: default limit 20, range 1..100, stable `(created_at,id)` ascending, opaque base64url JSON cursor containing position and hash of normalized filters/effective authorization scope. Waitlist lists use `(joined_at,id)` instead. Reauthorize every page; malformed/changed scope/filter cursor 400. No snapshot guarantee. Queue snapshot pagination has the stronger rules below.

## Waitlists and automatic promotion

`Waitlist={id:ID,slot_id:ID,patient_id:ID,state:waiting|promoted|withdrawn|skipped,joined_at:Time,promoted_appointment_id:ID|null,skip_reason:null|inactive_patient|patient_overlap|slot_retired|window_closed,version:Version}`.

| Method/path | Exact body/query and precondition | Success | Scope and conflicts |
|---|---|---|---|
| POST `/api/v1/appointments/waitlists` | `{patient_id:ID,slot_id:ID,expected_schedule_revision:Version}`; no parent ETag | 201 Waitlist | Self patient/receptionist; occupied future bookable slot required; duplicate waiting/already booked 409 already_waiting/already_booked; free slot 409 slot_available; wrong revision 409 schedule_changed |
| GET `/api/v1/appointments/waitlists` | patient_id?, slot_id?, state?, cursor?, limit? | 200 Page<Waitlist> | Self lists own only; receptionist; own doctor lists only their slots |
| GET `/api/v1/appointments/waitlists/{entry_id}` | None | 200 Waitlist | Same stored-resource scope |
| POST `/api/v1/appointments/waitlists/{entry_id}/withdraw` | `{reason:Reason}`; waitlist If-Match | 200 Waitlist | Self/receptionist; waiting -> withdrawn; withdrawn is stable no-op at current ETag; promoted/skipped 409 invalid_transition |

No public promote endpoint. FIFO `(joined_at,id)`, no priority, triage, notification service or acceptance-offer timer. Promotion creates a confirmed booking for the first eligible patient and marks entry promoted in the same transaction as slot release. It never asks a second service to book.

Join validates Patient and Doctor via current delegated Phase 2 APIs before locks. Promotion uses recent Patient-owned eligibility snapshots, maximum age 60 seconds. This is bounded eventual eligibility, not globally atomic deactivation. Patient batch version is the current user aggregate version for a mapped patient (missing profile/user is inactive/version0); active includes current patient role. Merge snapshots monotonically by source_version and reject older refreshes; an inactive newer version cannot be overwritten by an older active response. Before a cancellation/reschedule transaction, fetch eligibility for at most 50 FIFO candidates using the private batch leaf below; then reacquire locks and verify candidate IDs/versions still match. Candidate changes require bounded transaction restart. No network within locks. For patient overlap/inactive, use a savepoint around insertion; mark skipped with reason, continue. Process at most 50 entries per transaction. Unknown/stale status stops at that FIFO entry: do not skip or let a later arrival bypass it.

Cancellation/rescheduling must remain locally available when eligibility refresh fails: release/move the old booking and mark its slot `promotion_pending` in the local promotion_jobs table, retaining fairness. If a validated batch exists, attempt atomic promotion during that release transaction. Otherwise return the committed v1 booking response; waiting rows expose the pending work through a new slot status route. Direct book/reschedule target with any waiting row or pending job returns 409 waitlist_pending. Never expose that slot as available while blocked. Background worker claims a job in a short lease transaction, fetches eligibility outside locks, then reacquires normal locks and rechecks. Lease expiry recovers crash; DB state, not lease alone, controls fairness. Durable unique `(slot_id)` job, version and next_attempt_at; no Redis locks. Worker scans free bookable slots with waiting entries every five seconds to repair lost wakeups. Retries exponential 1..60 seconds; never discard pending jobs. If candidates exceed 50, persist continuation and keep slot blocked. Past/retired slots mark remaining waiting entries skipped in bounded batches. No promotion after starts_at.

| Method/path | Body/query | Success | Scope |
|---|---|---|---|
| GET `/api/v1/appointments/waitlist-slots/{slot_id}` | None | 200 `{slot_id:ID,waiting_count:integer,promotion_pending:boolean,accepted_revision:Version,observed_at:Time}` | Authenticated current patient/receptionist/own doctor; counts only, no identities |

Retirement and schedule revision changes serialize under doctor/slot locks. Entries refer to the original slot interval, not a revision: unchanged slots can promote under the latest accepted revision; retired intervals skip. Same patient/slot cannot have an active booking and waiting entry. Promotion withdrawal race has exactly one winning state; same-key replays never recreate a booking. Patient/Doctor deactivation discovered later prevents check-in and raises workflow review; no automatic deletion or cancellation of clinical history.

## Workflow and secure check-in

`Workflow={appointment_id:ID,journey_id:ID,patient_id:ID,doctor_id:ID,state:booked|checked_in|in_consultation|completed|cancelled|no_show,checkin_window:{starts_at:Time,ends_at:Time},queue_entry_id:ID|null,version:Version}`.

`TokenIssue={link_id:ID,appointment_id:ID,expires_at:Time,token:string,landing_path:string,version:Version}` is first-response only. Token is fixed 22-character Base62 encoding of 128 cryptographically random bits, padded with leading zero characters; reject noncanonical values/out-of-range encoding. Hash SHA-256 at rest. Purpose is check_in, bound to appointment and patient and the workflow version/schedule fingerprint at issue. It is not a JWT, appointment ID or shortener slug.

`CheckinResult={workflow:Workflow,queue_entry:QueueEntry}`; ETag is workflow.version. Token issuance ETag is link.version, but issuance precondition is workflow.version as a child command. Reissue revokes all unconsumed prior links under the workflow lock, increments workflow version, issues at that resulting version. Token is valid against that resulting version only. Workflow GET supplies the updated ETag for redemption.

| Method/path | Body/query and precondition | Success | Scope and conflicts |
|---|---|---|---|
| GET `/api/v1/appointments/{appointment_id}/workflow` | None | 200 Workflow | Self/receptionist/own doctor; unenrolled 404 |
| POST `/api/v1/appointments/{appointment_id}/workflow-enrollment` | `{}`; v1 appointment If-Match | 201 Workflow | Receptionist; future confirmed/no hold only; existing workflow returns 200 with new key/current booking ETag; otherwise 409 enrollment_unavailable |
| POST `/api/v1/appointments/{appointment_id}/check-in-links` | `{}`; workflow If-Match | 201 TokenIssue | Self/receptionist; booked only; now < window end; 409 invalid_transition |
| POST `/api/v1/appointments/{appointment_id}/check-in` | `{token:string}`; workflow If-Match | 200 CheckinResult | Self/receptionist; booked, valid link/window/active Patient and Doctor; 409 token_invalid/checkin_window_closed/invalid_transition |
| POST `/api/v1/appointments/{appointment_id}/staff-check-in` | `{reason:Reason}`; workflow If-Match | 200 CheckinResult | Receptionist only; same eligibility/window/transaction rules; audited fallback without token |

Check-in window `[starts_at - 30 minutes, starts_at + 15 minutes)` in UTC. Issue expiry `min(now + 24 hours, window.ends_at)`. Issuance before the window is permitted; redemption before window start/at-or-after end fails. Persist absolute window on workflow, recompute/invalidate links on reschedule. No client-clock decisions. Invalid/expired/revoked/consumed token gives identical token_invalid after authorized resource lookup. Same-key successful redemption replays the saved CheckinResult after authorization even though token is consumed; any different key cannot reuse it. Consume token, transition workflow, allocate counter, insert one queue entry, update local journey, audit/outbox/result atomically. Staff fallback also revokes outstanding tokens. Wrong patient cannot probe token validity.

Token issuance never persists raw secret in idempotency response. Equal-key replay returns 409 token_response_unavailable with details `{resource_id:link_id}`, with no new link; body mismatch remains conflict. Lost first response requires explicit new-key reissue and old-token revocation. Never auto-retry issuance. Receipt can be displayed in memory only; clear on logout/page exit. GET is not a resolver or consumption API.

Landing path is `/patient/check-in#appointment_id=<ID>&token=<TOKEN>` on the configured same origin. Frontend reads fragment, immediately replaces URL with `/patient/check-in`, holds secret only in memory, then requires authentication and explicit confirmation. If login navigation loses it, re-scan or reissue; never save it in local/session storage, logs, analytics, traces or error reports. No token in path/query, no arbitrary redirect URL. Referrer-Policy no-referrer and no-store. QR encodes this landing URL; manual copy/paste fallback is required. No camera permission/scanner dependency required. Later shortener can map an opaque alias to this landing contract in a reviewed phase; `/s/{token}` is neither implemented nor required here.

## Live consultation queues

No manual completion endpoint, reorder, urgent-priority algorithm, pause/resume or arbitrary doctor reassignment. Start must choose oldest waiting entry for that doctor/day, with no other in_consultation entry for that doctor on any day. No-show is explicit staff judgment, no GET/time-only automatic transition. Waiting checked-in cancellation uses existing cancel command with booking ETag, only if no clinical hold and not in_consultation; it atomically cancels workflow/queue and revokes links. Reschedule after checked_in returns 409 workflow_locked. Clinical hold remains a stronger blocker. Completed/no_show workflow blocks further cancel/reschedule (409 workflow_locked); v1 state remains confirmed until a permitted pre-consultation cancellation.

Workflow machine: booked -> checked_in -> in_consultation -> completed; booked/checked_in -> cancelled or no_show under stated gates. Terminal states do not reopen clinical queue. Records finalized snapshot, matching appointment/patient/doctor/consultation and a finalized local hold, is the only completion source. Legacy enrolled? Enrollment rejects holds, so existing unenrolled finalizations cannot accidentally complete another queue. If Records commits but hold completion/reconciliation fails, retain in_consultation and show pending; retry same Records finalize command and reconciliation. Doctor remains busy until confirmed completion. Never free queue because HTTP finalize was attempted.

Polling is the Phase 3 live transport. Patient polls own queue/workflow every 5 seconds; staff polls current queue first page every 3 seconds while visible. One request in flight per view; stop on unmount/logout; pause hidden tabs, refresh on visibility; transport errors back off 5,10,20,30 seconds with jitter; 401 uses existing single-flight refresh once, 403 stops. Abort superseded requests; stale responses cannot overwrite newer versions. Display observed_at and stale after 15 seconds without a successful refresh. No SSE/WebSocket endpoints: polling retains existing bearer/current-authority semantics, avoids connection fanout/reconnect infrastructure and is proportionate to one synthetic hospital. No latency guarantee; future measured need may justify authenticated SSE separately. Redis/RabbitMQ outages do not affect local queue correctness.

Reconciliation queries Records first (discovers prescription), Pharmacy if needed, Billing last; validates complete membership and identity. Store source versions/resource maps/expected-charge set/fetch times in Appointment. Each owner exports an atomic local snapshot with a monotonic episode revision incremented by any relevant local mutation. Every partial source page shares that revision; changed revision discards the batch and retries boundedly. Older revisions cannot overwrite newer. No invented event IDs for REST reconciliation. Compare source revision vector under local journey lock before applying; changed local version returns 412 for public reconcile, worker retries. Missing owner means preserve last known source and mark pending/owner_unavailable. Reconcile may commit that degraded state and return 200; it never authorizes discharge. No external success implied.

Worker scans enrolled active/reopened/discharged journeys every 10 seconds, <=20 episodes per batch, one DB lease per episode, bounded REST outside locks, backoff 1..60 seconds. Discharged journeys continue periodic checks to detect late source changes. Snapshot poll results, per-stage effects, audit/outbox and worker durable progress commit atomically. Leases recover restarts; no reliance on volatile timers for correctness. Proposed frequencies are not measured SLAs. On discharge fetch a fresh complete source vector (<=5 seconds old by commit), compare local episode/queue/hold plus vectors under locks. Source outage or stale/changed membership blocks. Cross-owner snapshots are not a global snapshot: a change after validation can still reopen the journey at the next reconciliation. State this limitation in UI and do not claim global atomic discharge.

## Exact new private leaves and security

Keep existing service JWT issuer/audience/key/caller binding, token_use service, 60-second lifetime (120-second verifier bound), exactly one scope and no public gateway routing. New service-only background read scopes below are narrowly allowlisted, audited and metadata-only. They do not impersonate a clinician or grant clinical content. Public initiating commands perform current-authority checks before calls. Delegated routes additionally verify X-Delegated-Authorization with existing user JWT; worker routes reject use as arbitrary user-driven clinical lookup. Leaves access only their own database and never recursively call another owner.
