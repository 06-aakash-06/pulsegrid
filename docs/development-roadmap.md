## Incremental rules

Deliver contract, migration, local implementation, authorization checks, tests and documentation together per workflow. Outbox, inbox, idempotency, audit, health and trace headers are prerequisites for the first operation requiring them, not a late retrofit. Monitoring instrumentation starts with scaffold and matures through each phase; Phase 8 builds the full control room. Do not implement all seven algorithms as isolated demos. Record benchmark baselines before optimization. Protect main from partial parallel-agent changes through reviewed integration commits, with no online publication unless separately authorized.

## Parallel Phase 1.2 scaffold ownership

The Agent A and Agent B tasks below started from the same Phase 1.1 commit in separate Git worktrees and branches (`foundation/backend-scaffold` and `foundation/frontend-scaffold`). Their completed commits were integrated onto `main` during Phase 1.4A. The original ownership boundaries remain useful for reference; no later task is authorized automatically. The integrator owns shared root files, contracts, and infrastructure.

**Agent A: Backend microservice scaffolding (Phase 1.2).** Exclusive ownership: `services/patient/`, `services/doctor/`, `services/appointment/`, `services/records/`, `services/pharmacy/`, `services/billing/`, `services/emergency/`, including each package's metadata, README, configuration skeleton and colocated smoke tests. Create independently packaged minimal FastAPI applications with service name/version and process liveness routes, configuration interfaces and structured request/trace header handling. Database readiness must explicitly report unconfigured until real adapters exist. Do not add domain functionality, databases/migrations, algorithms, Compose or a shared domain package. Backend dependencies may be declared; installation needs the later task's scope. Put backend instructions only inside the owned directories.

**Agent B: Frontend application scaffolding (Phase 1.2).** Exclusive ownership: `frontend/`, including package metadata/lockfile if authorized, React/TypeScript entrypoint, API configuration interfaces, accessible navigation shells for patient/staff/control-room routes, and colocated smoke tests/README. Display clear unconnected/pending states; do not invent live patient data, metrics or working workflows. Do not implement hospital functionality, server authorization or distributed algorithms. Frontend dependencies may be declared; installation needs the later task's scope. Put frontend instructions only inside the owned directory.

Neither agent edited `docs/`, root files, `contracts/`, `infra/`, `tests/`, `experiments/` or the other's directories. The integrator reviewed and tested the imported scaffolds. Deployment was added during Phase 1.4B. Shared executable API/event schemas remain separate integrator work; future tasks must report executed tests, unavailable tools and limitations precisely.
