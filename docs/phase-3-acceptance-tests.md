## Layer and environment requirements

Unit tests exercise transition tables/pure projections/token parsing; service contract tests exercise exact schemas/roles/headers/errors through FastAPI. PostgreSQL integration tests use real migrations/runtime roles and independent connections/app instances for locks/unique/GiST/partial indexes, with persisted counts and audit/outbox/idempotency checks. Mocked databases do not prove concurrency. Owner transport fixtures cover timeout/malformed responses for local failure handling; root integration uses actual private HTTP/service JWTs/delegation and gateway APIs. Browser workflows use real owner data without production mocks.

Each service feature agent runs tests only in its owned test directories; Agent 1 owns shared Appointment fixtures/test infrastructure and all migrations. Unique disposable test database/ports/IDs; never reset retained Compose DBs. Any separate isolated database lifecycle requires later implementation verification authorization. Only integrator runs/deploys shared topology, upgrades retained data and performs root/browser/full regression gates. No chaos/load claims; fault transports or controlled test process restart prove only the tested failure. Broker delivery tests stay skipped until Phase 5; pending outbox rows must not be marked published.

For every command assert exact status/body/ETag, actor/resource scope, persisted state/version, one durable response, audit chain integrity and outbox payload. For rolled-back commands assert no partial business rows, token/counter/stock/ledger changes or success result. Repeat retries after app restart. State-machine suites enumerate every allowed edge and reject all other edges rather than testing only happy paths.

## Required full integration journeys

Integrator records exact commit, topology, migration heads, commands, test totals, owner HTTP evidence and screenshot/browser observations without secrets. Required journeys use real service APIs:

1. Two synthetic patients compete for occupied slot/waitlist; cancellation automatically promotes FIFO, creates confirmed booking/real journey; retries preserve one effect and other patient cannot read it.
2. Promoted patient issues QR, lands without mutation, confirms secure check-in, sees own queue/position. Receptionist staff fallback on another appointment verifies scope and race behavior.
3. Assigned doctor starts head; wrong doctor cannot. Records draft/finalize with optional prescription; queue remains busy until real finalized snapshot/hold recovery, then completes exactly once.
4. Pharmacist reserves/partially fulfills/revalidates/dispenses; patient journey shows pending until all prescribed quantities fulfilled. Revoked unfilled versus already-dispensed cases have distinct release/review behavior.
5. Billing explicitly creates/imports consultation and all dispensing sources, simulates declined/success payment; paid missing-source invoice stays pending, full coverage allows reception administrative discharge. Late source/amendment/revocation reopens projection and does not rewrite clinical history.
6. Owner outage leaves safe local views/commands usable where specified, blocks unsafe writes/discharge, and periodic reconciliation recovers using actual owner versions after repair. Use authorized test fault scope only; no unrequested container termination/chaos.
